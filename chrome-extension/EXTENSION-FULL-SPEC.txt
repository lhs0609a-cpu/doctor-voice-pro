웹앱(Next.js)에서 "발행" 버튼을 누르면,

  웹앱 --(chrome.runtime.sendMessage, 외부 메시지)--> 확장 background.js
       --> 네이버 블로그 글쓰기 탭을 열고
       --> (로그인 안 돼 있으면) 자동/수동 로그인 후 글쓰기로 복귀
       --> chrome.debugger(CDP)로 "사람이 타이핑하듯" 제목·본문 입력
       --> 이미지는 합성 DragEvent 로 드롭 삽입
       --> 발행 레이어를 열어 카테고리/공개설정/예약시간 지정
       --> 임시저장 | 즉시발행 | 예약발행 실행
       --> 건별 결과를 웹앱으로 되돌려 보냄(CustomEvent)

여기에 부가 기능 2개:
  - Gemini(gemini.google.com)를 자동 조작해 키워드 N건의 블로그 글을 대량 생성
  - crx + updates.xml + 그룹정책 레지스트리로 무음 자동업데이트 배포

핵심 설계 원칙 (이식할 때도 반드시 유지):
  ① 입력은 반드시 CDP(chrome.debugger). DOM 직접 대입은 SmartEditor ONE / Quill
     둘 다 무시한다. 이건 취향이 아니라 유일하게 동작하는 경로다.
  ② 셀렉터는 data-click-area / data-name / data-testid 만 쓴다.
     해시 클래스(.save_btn__bzc5B 등)는 폴백으로만. 배포마다 바뀐다.
  ③ 실패는 조용히 넘기지 말고 "발행을 중단"한다.
     사진 빠진 글, 엉뚱한 카테고리, 즉시 발행돼버린 예약글은 수동 복구가 지옥이다.
  ④ 비밀번호는 서버에 절대 안 보낸다. 확장 로컬 storage 에 AES-GCM 암호화.
  ⑤ 긴 배치는 반드시 keepalive 로 감싼다. MV3 워커는 30초 유휴면 죽는다.

  같은 오리진(blog.naver.com)이라 window.frameElement 접근이 되므로,
  좌표 계산 시 iframe 오프셋을 더해 "뷰포트 절대 좌표"를 만들 수 있다(CDP 는 절대좌표를 씀).

  ★ .pem 을 분실하면 ID가 바뀌고, 기존 사용자 전원이 재설치해야 한다.

║ 4. 왜 CDP 인가 (가장 중요한 설계 결정)                                       ║
╚══════════════════════════════════════════════════════════════════════════════╝

네이버 SmartEditor ONE:
  키입력을 눈에 안 보이는 버퍼(#input_buffer... iframe + hidden contenteditable)로 캡처한다.
  .se-text-paragraph 에 textContent 를 대입해도 에디터 내부 모델에 반영되지 않는다.
  → 저장/발행하면 빈 글이 나간다.

Gemini 입력창:
  Quill 에디터. 내부 Delta 모델과 DOM 이 분리돼 있어 textContent 대입은 전송조차 안 된다.

해법: chrome.debugger(CDP) 1.3 을 탭에 attach 하고
  Input.dispatchMouseEvent  → 문단 클릭(캐럿 놓기)
  Input.insertText           → 텍스트 삽입 (IME 조합 문제 없음, 한글 안전)
  Input.dispatchKeyEvent     → Enter / Ctrl+A / Ctrl+B

주의사항 4개:
  (1) 좌표는 "뷰포트 절대좌표"다. iframe 안 요소라면 frameElement 오프셋을 더해야 한다.
  (2) 이미지 드롭(DragEvent)은 일반 DOM 이벤트라 CDP 가 붙어 있으면 방해된다.
      → 이미지 삽입 전 detach, 삽입 후 다시 attach.
  (3) attach 는 탭당 하나. 새로 붙이기 전에 기존 것을 반드시 detach.
  (4) 사용자에게 "디버깅 중" 배너가 보인다. 필요한 최소 구간만 붙여 배너 노출을 줄인다.

CDP 헬퍼 전문 (background.js — 이식할 때 그대로 복사):

  function cdp(tabId, method, params) {
    return new Promise((resolve, reject) => {
      chrome.debugger.sendCommand({ tabId }, method, params || {}, (res) => {
        if (chrome.runtime.lastError) reject(new Error(chrome.runtime.lastError.message));
        else resolve(res);
      });
    });
  }

  let debuggerTabId = null;
  async function attachDebugger(tabId) {
    if (debuggerTabId) { try { await detachDebugger(debuggerTabId); } catch (_) {} }
    await new Promise((resolve, reject) => {
      chrome.debugger.attach({ tabId }, '1.3', () => {
        if (chrome.runtime.lastError) reject(new Error(chrome.runtime.lastError.message));
        else { debuggerTabId = tabId; resolve(); }
      });
    });
  }
  async function detachDebugger(tabId) {
    await new Promise((resolve) => {
      chrome.debugger.detach({ tabId }, () => { debuggerTabId = null; resolve(); });
    });
  }
  async function clickAt(tabId, x, y) {
    await cdp(tabId, 'Input.dispatchMouseEvent', { type:'mousePressed',  x, y, button:'left', clickCount:1 });
    await sleep(40);
    await cdp(tabId, 'Input.dispatchMouseEvent', { type:'mouseReleased', x, y, button:'left', clickCount:1 });
  }
  async function insertText(tabId, text) {
    if (!text) return;
    await cdp(tabId, 'Input.insertText', { text });
  }
  async function pressEnter(tabId) {
    await cdp(tabId,'Input.dispatchKeyEvent',{type:'keyDown',key:'Enter',code:'Enter',windowsVirtualKeyCode:13,nativeVirtualKeyCode:13});
    await cdp(tabId,'Input.dispatchKeyEvent',{type:'keyUp'  ,key:'Enter',code:'Enter',windowsVirtualKeyCode:13,nativeVirtualKeyCode:13});
  }
  async function ctrlA(tabId) {
    await cdp(tabId,'Input.dispatchKeyEvent',{type:'keyDown',key:'Control',code:'ControlLeft',windowsVirtualKeyCode:17,modifiers:2});
    await cdp(tabId,'Input.dispatchKeyEvent',{type:'keyDown',key:'a',code:'KeyA',windowsVirtualKeyCode:65,modifiers:2});
    await sleep(40);
    await cdp(tabId,'Input.dispatchKeyEvent',{type:'keyUp',key:'a',code:'KeyA',windowsVirtualKeyCode:65,modifiers:2});
    await cdp(tabId,'Input.dispatchKeyEvent',{type:'keyUp',key:'Control',code:'ControlLeft',windowsVirtualKeyCode:17,modifiers:0});
  }
  // Ctrl+B = 굵게 토글 (키워드 강조에 사용)
  async function ctrlB(tabId) { /* 위와 동일, KeyB / 66 */ }

  chrome.debugger.onDetach.addListener(() => { debuggerTabId = null; });

  // content script 에 메시지. 응답 안 하는 프레임은 null 로 흘린다.
  function sendToTab(tabId, message) {
    return new Promise((resolve) => {
      chrome.tabs.sendMessage(tabId, message, (res) => {
        if (chrome.runtime.lastError) resolve(null); else resolve(res);
      });
    });
  }

  // iframe 오프셋을 더한 절대좌표 (naver-poster.js)
  function absoluteRect(el) {
    const r = el.getBoundingClientRect();
    let offX = 0, offY = 0;
    try {
      if (window.frameElement) {
        const fr = window.frameElement.getBoundingClientRect();
        offX = fr.left; offY = fr.top;
      }
    } catch (e) { /* cross-origin → 오프셋 0 */ }
    return {
      x: Math.round(offX + r.left + r.width / 2),
      y: Math.round(offY + r.top + Math.min(r.height / 2, 24)),
      left: offX + r.left, top: offY + r.top, width: r.width, height: r.height,
    };
  }

  function sendToExtension(msg) {
    return new Promise((resolve, reject) => {
      const id = localStorage.getItem('doctorvoice-extension-id');
      if (!id || !window.chrome?.runtime?.sendMessage)
        return reject(new Error('확장 프로그램이 연결되지 않았습니다'));
      chrome.runtime.sendMessage(id, msg, (res) => {
        if (chrome.runtime.lastError) reject(chrome.runtime.lastError);
        else resolve(res);
      });
    });
  }

  // (c) 이미지 → EXIF 제거된 base64 (반드시 canvas 를 거친다)
  function imageToCleanBase64(file, maxWidth = 1280, quality = 0.9) {
    return new Promise((resolve, reject) => {
      const img = new Image();
      img.onload = () => {
        let w = img.width, h = img.height;
        if (w > maxWidth) { h = Math.round(h * maxWidth / w); w = maxWidth; }
        const c = document.createElement('canvas');
        c.width = w; c.height = h;
        const ctx = c.getContext('2d');
        if (!ctx) return reject(new Error('canvas 미지원'));
        ctx.drawImage(img, 0, 0, w, h);
        resolve(c.toDataURL('image/jpeg', quality));   // ← EXIF(GPS/기기) 제거됨
      };
      img.onerror = reject;
      img.src = URL.createObjectURL(file);
    });
  }

normalizeJob 정규화 규칙:
  - blocks 가 있으면 content = text 블록들을 "\n\n" 으로 join,
    images = image 블록들의 배열 → 즉 blocks 만 보내면 중복 전송 안 해도 된다.
    ★ blocks 를 보낼 때 images 를 같이 보내면 같은 base64 가 두 번 실려 전송량 2배.
  - finalAction 기본값 'draft' (안전). 명시 안 하면 발행되지 않는다.
  - options.openType 기본 'public', options.search 기본 true, category 기본 null.

── 7-3. 자격증명 로컬 암호화 (AES-GCM) — background.js ───────────────────────

  원칙: 서버 DB 에 절대 저장하지 않는다. 확장 로컬 storage 에만, 암호화해서.
  한계: 키도 같은 storage 에 있으므로 "같은 기기 사용자"에게는 완전 안전하지 않다.
        → 반드시 opt-in(사용자가 팝업에서 직접 저장)으로만 제공한다.

  const _b64   = (buf) => btoa(String.fromCharCode(...new Uint8Array(buf)));
  const _unb64 = (str) => Uint8Array.from(atob(str), (c) => c.charCodeAt(0));

  async function _getCredKey() {                      // 설치별 1회 생성 후 재사용
    const stored = (await chrome.storage.local.get('__credKey')).__credKey;
    if (stored) return crypto.subtle.importKey('raw', _unb64(stored), 'AES-GCM', true,
                                               ['encrypt','decrypt']);
    const key = await crypto.subtle.generateKey({name:'AES-GCM',length:256}, true,
                                                ['encrypt','decrypt']);
    const raw = await crypto.subtle.exportKey('raw', key);
    await chrome.storage.local.set({ __credKey: _b64(raw) });
    return key;
  }
  async function _enc(text) {
    const key = await _getCredKey();
    const iv  = crypto.getRandomValues(new Uint8Array(12));      // GCM 은 IV 12바이트
    const ct  = await crypto.subtle.encrypt({name:'AES-GCM', iv}, key,
                                            new TextEncoder().encode(text || ''));
    return { iv: _b64(iv), ct: _b64(ct) };
  }
  async function _dec(enc) {
    if (!enc?.iv || !enc?.ct) return '';
    try {
      const key = await _getCredKey();
      const pt = await crypto.subtle.decrypt({name:'AES-GCM', iv:_unb64(enc.iv)},
                                             key, _unb64(enc.ct));
      return new TextDecoder().decode(pt);
    } catch (e) { return ''; }
  }
  async function saveNaverCred(id, pw) {
    if (!id || !pw) throw new Error('아이디/비밀번호가 필요합니다.');
    await chrome.storage.local.set({ naverCred: { id: await _enc(id), pw: await _enc(pw) } });
  }
  async function getNaverCred() {
    const enc = (await chrome.storage.local.get('naverCred')).naverCred;
    if (!enc) return null;
    const id = await _dec(enc.id), pw = await _dec(enc.pw);
    return (id && pw) ? { id, pw } : null;
  }

  ★ 함정: 확장을 "새 폴더로 교체" 하면 크롬이 확장 storage 를 통째로 비운다.
    → 저장한 계정이 소리 없이 사라지고 다음 발행이 로그인 화면에서 멈춘다.

── 8-3. 본문 입력 + 키워드 자동 굵게 (background.js typeBody) ────────────────

  줄바꿈(\n) = Enter 1회 = 문단 분리. emphasize 단어는 Ctrl+B 로 감싼다.

  function escapeRe(s) { return s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'); }

  async function typeBody(tabId, content, emphasize) {
    const words = (Array.isArray(emphasize) ? emphasize : [])
      .filter((w) => typeof w === 'string' && w.trim().length >= 2).map((w) => w.trim());
    const uniq = [...new Set(words)].sort((a,b) => b.length - a.length); // 긴 단어 우선
    const re = uniq.length ? new RegExp('(' + uniq.map(escapeRe).join('|') + ')') : null;
    const wordSet = new Set(uniq);

    const lines = (content || '').split('\n');
    for (let i = 0; i < lines.length; i++) {
      const line = lines[i];
      if (line.length) {
        if (re) {
          for (const part of line.split(re)) {          // split 에 캡처그룹 → 구분자 보존
            if (!part) continue;
            if (wordSet.has(part)) { await ctrlB(tabId); await insertText(tabId, part); await ctrlB(tabId); }
            else await insertText(tabId, part);
          }
        } else await insertText(tabId, line);
      }
      if (i < lines.length - 1) { await pressEnter(tabId); await sleep(30); }
    }
  }

  ★ 긴 단어부터 정렬하는 이유: "치과" 와 "치과교정" 이 둘 다 있을 때
    짧은 것이 먼저 매칭되면 "치과"+"교정" 으로 쪼개져 굵게가 어긋난다.

── 8-4. 글-이미지 인터리브 (typeBlocksInterleaved) ───────────────────────────

  글 → 이미지 → 글 → 이미지 순서로 넣는다. CDP(텍스트)와 DOM 드롭(이미지)이
  서로 방해하므로 이미지 구간마다 detach/attach 를 반복한다.

  async function typeBlocksInterleaved(tabId, job) {
    const blocks = job.blocks || [];
    let first = true, cleared = false, prevType = null;
    for (const b of blocks) {
      if (b.type === 'text' && b.content) {
        if (!first) {
          await pressEnter(tabId); await sleep(40);
          // 글 다음에 바로 글이면 Enter 두 번 = 빈 줄 유지
          // (본문이 '두 문장마다 빈 줄'로 정리돼 오는데, 한 번만 치면 문단 경계에서
          //  그 빈 줄이 사라져 모바일 가독성이 무너진다)
          if (prevType === 'text') { await pressEnter(tabId); await sleep(40); }
        }
        await typeBody(tabId, b.content, job.emphasize);
        first = false; cleared = true; prevType = 'text';
      } else if (b.type === 'image' && b.image) {
        if (!cleared) { await insertText(tabId, ''); cleared = true; } // ctrlA 선택분 제거
        if (!first) { await pressEnter(tabId); await sleep(40); }
        try { await detachDebugger(tabId); } catch (_) {}             // ★ 드롭 전 분리
        await sleep(150);
        const r = await sendToTab(tabId, { action:'INSERT_IMAGES', images:[b.image], atCaret:true });
        assertImagesInserted(r, 1);                                    // 실패 시 throw
        await sleep(400);
        await attachDebugger(tabId); await sleep(200);                 // ★ 재부착
        first = false; prevType = 'image';
      }
    }
  }

── 8-5. 이미지 삽입 (naver-poster.js) ────────────────────────────────────────

  방식: base64 → File → DataTransfer → 합성 DragEvent(dragenter/dragover/drop)
  삽입 위치: atCaret=true 면 현재 캐럿 좌표, 아니면 에디터 하단

  function base64ToFile(dataUrl, name) {
    const [head, body] = dataUrl.split(',');
    const mime = (head.match(/data:(.*?);/) || [])[1] || 'image/jpeg';
    const bin = atob(body);
    const arr = new Uint8Array(bin.length);
    for (let i = 0; i < bin.length; i++) arr[i] = bin.charCodeAt(i);
    return new File([arr], name, { type: mime });
  }

  function caretPoint() {                         // 현재 커서의 화면 좌표
    try {
      const sel = window.getSelection();
      if (sel && sel.rangeCount) {
        const rect = sel.getRangeAt(0).getBoundingClientRect();
        if (rect && (rect.top || rect.left) && rect.top > 0)
          return { x: rect.left + 2, y: rect.top + rect.height / 2 };
      }
    } catch (e) {}
    return null;
  }

  async function dropImage(file, atCaret) {
    const target = document.querySelector('.se-content .se-components-wrap')
                || document.querySelector('.se-content')
                || document.querySelector('.se-dnd-wrap')
                || document.querySelector('.se-component.se-text');
    if (!target) throw new Error('드롭 대상 없음');
    const dt = new DataTransfer(); dt.items.add(file);
    let x, y;
    const cp = atCaret ? caretPoint() : null;
    if (cp) { x = cp.x; y = cp.y; }
    else { const r = target.getBoundingClientRect(); x = r.left + r.width/2; y = r.top + r.height - 8; }
    const opts = { bubbles:true, cancelable:true, composed:true, dataTransfer:dt, clientX:x, clientY:y };
    target.dispatchEvent(new DragEvent('dragenter', opts));
    target.dispatchEvent(new DragEvent('dragover',  opts));
    target.dispatchEvent(new DragEvent('drop',      opts));
  }

  // ★ 업로드 성공을 "실제로 이미지가 늘었는지"로 검증한다.
  //   예전엔 DragEvent 3개 쏘고 sleep(1800) 만 기다려서, 0장 들어가도 성공으로 셌다.
  //   이미지 컴포넌트 클래스가 미확보라 3가지 신호의 최댓값을 쓴다(하나 빗나가도 방어).
  function imageComponentCount() {
    return Math.max(
      document.querySelectorAll('.se-component.se-image').length,
      document.querySelectorAll('.se-component[class*="image" i]').length,
      document.querySelectorAll('.se-content img, .se-components-wrap img').length
    );
  }
  async function dropImageVerified(file, atCaret, timeoutMs) {
    const before = imageComponentCount();
    await dropImage(file, atCaret);
    const deadline = Date.now() + (timeoutMs || 25000);
    while (Date.now() < deadline) {
      await sleep(300);
      if (imageComponentCount() > before) return true;
    }
    return false;
  }

  // 장당 3회 재시도(점증 대기 2s/4s). 결과를 반드시 호출부에 돌려준다.
  async function insertImages(images, atCaret) {
    if (!images?.length) return { inserted:0, expected:0, failed:[] };
    let ok = 0; const failed = [];
    for (let i = 0; i < images.length; i++) {
      let placed = false, lastErr = '';
      for (let attempt = 1; attempt <= 3 && !placed; attempt++) {
        try {
          const file = base64ToFile(images[i], `image_${Date.now()}_${i}_${attempt}.jpg`);
          placed = await dropImageVerified(file, atCaret);
          if (!placed) lastErr = '업로드 확인 실패(시간 초과)';
        } catch (e) { lastErr = e.message; }
        if (!placed && attempt < 3) await sleep(2000 * attempt);
      }
      if (placed) { ok++; await sleep(600); }
      else failed.push({ index: i, error: lastErr });
    }
    return { inserted: ok, expected: images.length, failed };
  }

  // background 쪽 검증 — 한 장이라도 빠지면 발행하지 않는다
  function assertImagesInserted(res, expected) {
    if (!res) throw new Error('이미지 삽입 응답 없음 (탭이 닫혔거나 에디터 무응답)');
    const got = res.inserted || 0;
    if (got < expected) {
      const why = res.failed?.[0]?.error || '원인 불명';
      throw new Error(`이미지 ${expected}장 중 ${got}장만 삽입됨 — ${why}`);
    }
  }

── 10-1. 왜 payload 를 나눠 받는가 (64MiB 문제) ──────────────────────────────

  100건 × 사진 10장 × 400KB(base64) ≈ 수백 MB.
  크롬 확장 메시지 한계는 64MiB → 한 번에 보내면 전송 자체가 실패한다.
  또 미리 다 만들어두면 웹앱 탭 메모리가 500MB 를 넘어 탭이 죽는다.

  해법: 2단 전송
    ① 웹앱 → 확장 : 사진 없는 메타데이터만 (100건이어도 수십 KB)
    ② 확장이 각 글을 처리하기 "직전"에 그 한 건의 payload 만 요청 (≈5MB)

  요청 경로:
    background: sendToTab(webTabId, {action:'REQUEST_JOB', id})
      → content-website.js: CustomEvent 'doctorvoice-job-request' {id, token}
        → 웹앱: IndexedDB 에서 사진 꺼내 blocks 조립
          → CustomEvent 'doctorvoice-job-payload' {token, job}
            → content-website.js: sendResponse({job})    ※ token 일치 확인 필수
  타임아웃: 웹앱이 30초 내 응답 안 하면 finish(null) → 그 건만 실패, 배치는 계속
  재시도 : background 가 2회까지 요청(첫 실패 후 1초 대기)

  function hasPayload(m) {   // 구버전 페이지는 통째로 보낸다 → 그대로 사용
    return !!(m && ((m.blocks && m.blocks.length) || (m.images && m.images.length) || m.content));
  }
  async function requestJobPayload(webTabId, id) {
    if (!webTabId) return null;
    for (let attempt = 1; attempt <= 2; attempt++) {
      try {
        const res = await sendToTab(webTabId, { action:'REQUEST_JOB', id });
        if (res && res.job) return res.job;
      } catch (e) {}
      if (attempt === 1) await sleep(1000);
    }
    return null;
  }

── 10-2. startBatch 루프 ─────────────────────────────────────────────────────

  async function startBatch(metas, sender) {
    if (batchRunning) return;
    batchRunning = true;
    startKeepAlive();                                   // ★ 배치 내내 워커 유지
    const webTabId = sender?.tab?.id || null;
    let missStreak = 0;
    try {
      for (let i = 0; i < metas.length; i++) {
        const meta = metas[i];
        let result;
        try {
          const raw = hasPayload(meta) ? meta : await requestJobPayload(webTabId, meta.id);
          const job = normalizeJob(raw);
          if (!job) throw new Error('글 데이터를 받지 못했습니다(닥터보이스 탭이 닫혔을 수 있습니다)');
          missStreak = 0;
          result = await runOne(job);
        } catch (e) { result = { ok:false, error:e.message }; missStreak++; }

        reportJobResult(webTabId, meta.id, !!result?.ok,
                        result?.error || result?.action || '', !!result?.uncertain);

        // 로그인이 풀렸으면 남은 건도 전부 같은 이유로 실패한다 → 즉시 중단
        if (result?.needLogin) {
          for (let k = i+1; k < metas.length; k++)
            reportJobResult(webTabId, metas[k].id, false,
              '네이버 로그인이 풀려 중단됨 — 로그인 후 다시 발행하세요');
          break;
        }
        // payload 3연속 실패 = 웹앱 탭이 닫힘 → 헛돌지 말고 중단
        if (missStreak >= 3 && i+1 < metas.length) {
          for (let k = i+1; k < metas.length; k++)
            reportJobResult(webTabId, metas[k].id, false, '닥터보이스 탭이 닫혀 중단됨');
          break;
        }
        await sleep(1500);          // 연속 등록 사이 여유(봇 감지 완화)
      }
    } finally {
      batchRunning = false;         // ★ 무슨 일이 있어도 반드시 푼다
      stopKeepAlive();              //   안 풀면 다음 발행이 영영 막힌다
    }
  }

── 10-3. 건당 가드 타임아웃 (jobGuardMs) ─────────────────────────────────────

  function jobGuardMs(job) {
    const imgs = (job.blocks||[]).filter(b => b.type==='image' && b.image).length
              || (job.images||[]).length;
    const base    = 180000;   // 페이지 로드 + 타이핑 + finalize
    const captcha = 200000;   // ★ finalize 의 캡차 대기(180초)보다 반드시 길게
    return base + captcha + imgs * 30000;   // 이미지 1장당 30초(재시도 3회 여유 포함)
  }
  // 사진 10장이면 11분 20초. 고정 180초였을 때의 사고:
  //  · 사진 30장이면 삽입만 120초 넘어 정상 작업이 timeout 으로 찍혔다
  //  · 캡차 대기가 정확히 180초라 캡차가 뜨면 반드시 가드가 먼저 터졌다
  // 가드가 터져도 runAutomation 은 계속 돌아 실제로는 발행이 끝난다
  //  → 프론트가 실패로 알고 재시도하면 같은 글이 두 번 예약된다
  //  → 그래서 이 경로는 uncertain:true 로 표시하고, 프론트는 자동 재시도 금지

  function runOne(job) {
    return new Promise((resolve) => {
      const guard = setTimeout(() => {
        if (jobDoneResolver) {
          const r = jobDoneResolver; jobDoneResolver = null;
          r({ ok:false, error:'timeout', uncertain:true });   // ★ uncertain
        }
      }, jobGuardMs(job));
      const gen = ++jobGen;                       // 건 세대 번호
      jobDoneResolver = (res) => { clearTimeout(guard); resolve(res); };
      startJob(job).then((tabId) => { if (tabId) watchLoginBounce(tabId, gen); })
                   .catch((e) => { /* 즉시 실패 처리 */ });
    });
  }
  // ★ jobGen 이 필요한 이유: 배치는 같은 탭을 재사용하므로, 앞 건의 watchLoginBounce
  //   감시자가 살아남아 다음 건을 대신 끝내버릴 수 있다. gen 을 비교해 손을 뗀다.

── 10-4. 결과 보고 ──────────────────────────────────────────────────────────

  function reportJobResult(webTabId, id, ok, message, uncertain) {
    const payload = { action:'JOB_RESULT', id, ok, message, uncertain: !!uncertain };
    if (webTabId) chrome.tabs.sendMessage(webTabId, payload, () => void chrome.runtime.lastError);
    else chrome.tabs.query({}, (tabs) => {      // sender 를 모르면 웹앱 탭을 찾는다
      const t = tabs.find(x => x.url && (x.url.includes('doctor-voice')
              || x.url.includes('vercel.app') || x.url.includes('localhost')));
      if (t) chrome.tabs.sendMessage(t.id, payload, () => void chrome.runtime.lastError);
    });
  }

  웹앱 측 처리 원칙:
    · 성공한 건만 준비함에서 제거. 실패한 건은 사유와 함께 남겨 재시도 가능하게.
      (예전엔 전송 직후 준비함을 통째로 비워서 실패한 글이 흔적 없이 사라졌다)
    · uncertain:true 는 "발행됐을 수도 있음" → 자동 재시도 금지, 사용자에게 확인 요청
    · stall 감시 타이머는 확장 가드 최댓값보다 길어야 한다. 현재 웹앱은 15분.
      (7분이었을 때: 정상적으로 오래 걸리는 글이 '응답 없음'으로 끊겨 화면만 풀리고,
       확장은 계속 발행하니 다시 누르면 같은 글이 두 번 예약됐다)
    · 배치 진행 상태를 localStorage['doctorvoice-batch-active'] 에 남긴다.
      발행 도중 새로고침하면 화면이 결과를 무시해 중복 발행이 발생했었다.

  async function ensureGeminiTab() {

  async function waitForGeminiReady(tabId, timeout, tempChat) {
    const started = Date.now();
    let sawAny = false, reloaded = false;
    while (Date.now() - started < timeout) {
      const r = await sendToTab(tabId, { action:'GEM_PING' });
      if (r) sawAny = true;
      if (r?.ok && r.ready) {
        if (!r.loggedIn) throw new Error('Gemini 에 로그인되어 있지 않습니다.');
        if (tempChat) await sendToTab(tabId, {action:'GEM_WAIT_READY', tempChat:true, timeout:5000});
        return true;
      }
      if (!sawAny && !reloaded && Date.now() - started > 4000) {
        reloaded = true;
        try { await chrome.tabs.reload(tabId); } catch (_) {}
        await sleep(3000);
      }
      await sleep(700);
    }
    throw new Error('Gemini 페이지가 준비되지 않았습니다. 로그인 확인 후 탭 새로고침하세요.');
  }

── 11-3. 1건 생성 (genOne) — 입력은 CDP, 전송은 Enter ────────────────────────

  async function genOne(tabId, prompt, timeoutMs) {
    const pos = await sendToTab(tabId, { action:'GEM_INPUT_POS' });
    if (!pos?.ok || !pos.pos) throw new Error(pos?.error || '입력창을 찾지 못했습니다');

    await attachDebugger(tabId);
    try {
      await clickAt(tabId, pos.pos.x, pos.pos.y);
      await sleep(200);
      await insertText(tabId, prompt);
      await sleep(400);                       // Quill 이 Delta 를 반영할 여유
      await pressEnter(tabId);                // ★ enterkeyhint="send" → 버튼 불필요
    } finally {
      try { await detachDebugger(tabId); } catch (_) {}   // 배너 오래 안 띄운다
    }

    // ★ 폴링 수확 (긴 단일 await 금지)
    //  · MV3 워커는 긴 유휴 await 중 종료될 수 있다. 잦은 메시지 왕복이 확실히 살려둔다
    //  · 프롬프트 전송 실패 시 응답이 시작조차 않으므로, 60초 내 '시작' 없으면 실패 처리
    const expectIndex = pos.count || 0;
    const started = Date.now();
    let sawStart = false, lastChars = -1;
    while (Date.now() - started < timeoutMs) {
      await sleep(1500);
      const st = await sendToTab(tabId, { action:'GEM_STATUS', expectIndex });
      if (!st?.ok) continue;
      if (st.started) sawStart = true;
      if (!sawStart && Date.now() - started > 60000)
        return { ok:false, text:'', chars:0, error:'응답이 시작되지 않았습니다(프롬프트 전송 실패 가능성)' };
      const cur = st.chars || 0;
      if (cur !== lastChars) {
        lastChars = cur;
        await sendToTab(tabId, { action:'GEM_PROGRESS',
          text:`생성 중… ${cur.toLocaleString()}자`, pct: Math.min(90, 20 + cur/40) });
      }
      if (st.complete && st.text) return { ok:true, text:st.text, chars:st.chars };
    }
    // 타임아웃 — 그때까지 나온 글이라도 넘겨 길이로 판단하게 한다
    const fin = await sendToTab(tabId, { action:'GEM_STATUS', expectIndex });
    const text = fin?.ok ? (fin.text || '') : '';
    return { ok:false, text, chars:text.length, error:'응답 완료 신호를 받지 못했습니다' };
  }

  function genTimeoutMs(prompt) {      // 프롬프트가 길수록 답도 길어진다
    return 180000 + Math.min(120000, Math.floor((prompt||'').length / 10) * 1000);
  }

── 11-5. 배치 루프 (startGenBatch) ──────────────────────────────────────────

── 13-1. MV3 keepalive ──────────────────────────────────────────────────────

  문제: MV3 서비스워커는 30초 유휴면 강제 종료된다. 배치가 통째로 멈추고
        Gemini 탭이 빈 채 방치되며, 결과도 에러도 오지 않아 화면이 영영 "생성 중".
  chrome.alarms 최소 주기(30초)는 유휴 한계와 정확히 겹쳐 경계에서 진다 → 단독으로 못 믿음.
  해법: 25초마다 무해한 확장 API 호출로 타이머를 리셋. 배치가 겹칠 수 있어 참조수로 on/off.

  let keepAliveTimer = null, keepAliveRefs = 0;
  function startKeepAlive() {
    keepAliveRefs++;
    if (keepAliveTimer) return;
    keepAliveTimer = setInterval(() => {
      chrome.runtime.getPlatformInfo(() => void chrome.runtime.lastError);
    }, 25000);
  }
  function stopKeepAlive() {
    keepAliveRefs = Math.max(0, keepAliveRefs - 1);
    if (keepAliveRefs === 0 && keepAliveTimer) {
      clearInterval(keepAliveTimer); keepAliveTimer = null;
    }
  }
  // 알람은 backstop 일 뿐:  chrome.alarms.create('keepAlive', { periodInMinutes: 0.5 });
  // ★ 새로 수십 분 넘게 도는 background 루프를 만들면 시작 직후 startKeepAlive(),
  //   finally 에서 stopKeepAlive(). 현재 적용: startGenBatch, startBatch.
  // ★ 추가 방어: 긴 단일 await 대신 짧은 폴링(1.5초)을 쓴다. 잦은 메시지 왕복이
  //   워커를 확실히 살려둔다(setInterval 만으로는 얼어붙을 수 있다).

── 13-2. 디스크 진단 로그 (고객 PC 원격 디버깅용) ───────────────────────────

  문제: 서비스워커 콘솔은 워커가 죽으면 같이 비고, 고객 PC 에서는 열어보게 하기도 어렵다.
        "발행 중인데 글이 안 써진다" 류는 그 순간의 기록이 없으면 영영 못 잡는다.
  해법: 모든 로그를 chrome.storage.local 에도 남기고, 팝업에서 통째로 클립보드 복사.

  const DIAG_KEY = 'diagLog', DIAG_MAX = 500, DIAG_MAX_LEN = 300;

  function diagFormat(v) {
    if (typeof v === 'string') return v;
    if (v instanceof Error) return v.message;
    try {
      // ★ 사진 base64 가 섞이면 수십 MB 가 된다 → 반드시 잘라 넣는다
      return JSON.stringify(v).replace(/data:[^"]{40,}/g, m => m.slice(0,30) + '…(생략)');
    } catch (e) { return String(v); }
  }
  function diagPush(parts) {
    const t = new Date();
    let line = `${String(t.getHours()).padStart(2,'0')}:${String(t.getMinutes()).padStart(2,'0')}:`
             + `${String(t.getSeconds()).padStart(2,'0')} ` + parts.map(diagFormat).join(' ');
    if (line.length > DIAG_MAX_LEN) line = line.slice(0, DIAG_MAX_LEN) + '…';
    diagQueue.push(line);
    if (!diagTimer) diagTimer = setTimeout(flushDiag, 1000);   // 1초 모아쓰기
  }
  async function flushDiag() {
    diagTimer = null;
    if (!diagQueue.length) return;
    // ★ 앞선 flush 와 겹치면 읽기-쓰기 사이에 줄이 사라진다 → 순서를 강제한다
    diagFlushing = (diagFlushing || Promise.resolve()).then(async () => {
      const mine = diagQueue; diagQueue = [];
      const cur = (await chrome.storage.local.get(DIAG_KEY))[DIAG_KEY] || [];
      await chrome.storage.local.set({ [DIAG_KEY]: cur.concat(mine).slice(-DIAG_MAX) });
    });
    return diagFlushing;
  }
  const log = (...a) => { console.log('[bg]', ...a); diagPush(a); };

  // ★ 워커 기동 줄은 모아쓰기를 기다리지 않고 즉시 저장한다.
  //   배치 로그 한가운데 이 줄이 있으면 = 워커가 도중에 죽었다는 뜻이고,
  //   진행 중이던 job 은 메모리와 함께 통째로 사라진 것이다. 가장 중요한 단서.
  log(`서비스워커 기동 v${VERSION}`);
  flushDiag();

  content script 도 background 로 한 줄씩 올린다:
    function diag(text) {
      try { chrome.runtime.sendMessage({action:'DIAG', text}, () => void chrome.runtime.lastError); }
      catch (e) {}
    }
    // "에디터를 못 찾음"인지 "찾았는데 입력이 안 됨"인지는 여기서만 갈린다.
    // ★ 최상위 문서에서만 보낸다 — 프레임마다 보내면 같은 줄로 도배된다.

── 13-3. "실패 시 중단" 원칙 목록 ───────────────────────────────────────────

  중단(throw)해야 하는 경우                 안 하면 생기는 일
  ─────────────────────────────────────────  ────────────────────────────────────
  예약 날짜 지정 실패                        네이버 기본값(오늘/지금) → 전건 즉시 발행
  예약 시/분 입력란 못 찾음                  같음

── 13-4. 기타 실전 함정 모음 ────────────────────────────────────────────────

  · sendResponse 조립 순서: { ...res, ok: res.done !== false }
    → { ok:true, ...res } 로 쓰면 실패가 성공으로 보고된다.
  · editorOnly 명령은 에디터 프레임 아니면 return(무응답).
    여러 프레임이 응답하면 먼저 온 답이 채택돼 엉뚱한 결과가 된다.
  · READ_BLOG_ID 는 blogId 를 찾은 프레임만 응답. 빈 값 선점 방지.
  · jobGen(세대 번호): 배치는 같은 탭을 재사용하므로 앞 건의 감시자가
    다음 건을 대신 끝내버릴 수 있다.
  · batchRunning / genRunning 은 반드시 finally 에서 해제.
    안 풀면 다음 발행이 영영 막힌다. 이미 돌고 있으면 조용히 무시하지 말고 사유를 응답한다
    (예전엔 페이지가 성공 토스트를 띄운 채 아무 일도 안 일어나 "발행이 안 된다"로 보였다).
  · VERSION 은 chrome.runtime.getManifest().version 에서 읽는다.
    상수로 박아두면 릴리스 때 manifest 만 올리고 코드를 빠뜨려
    "설치했는데도 계속 업데이트 필요"로 보이는 사고가 난다(v16.0.5 실제 발생).
  · PING 응답의 updateAvailable 은 캐시를 그대로 믿지 말고 compareVersion 으로 재계산.
    방금 새 버전을 깔았다면 캐시값은 업데이트 전에 계산된 것이라 계속 "업데이트 필요"로 남는다.
  · 배치 사이 sleep(1500) — 연속 등록 봇 감지 완화.
  · 웹앱 stall 타이머(15분) > 확장 가드 최댓값(11분+). 어기면 중복 예약 발생.
  · 확장 폴더 교체 = storage 초기화 = 저장된 계정 소실. 팝업에서 경고 표시.

── 14-2. [2층] version.json 폴링 → 웹앱/팝업 업데이트 안내 ───────────────────

  version.json:
    {
      "version": "16.0.7",
      "downloadUrl": ".../extension/doctorvoice-extension-v16.0.7.zip",
      "notes": "v16.0.7 — 발행이 멈추는 원인을 찾을 수 있게 '문제진단 로그' 추가 · ...",
      "minVersion": "15.0.0",

  background.js:
    const UPDATE_URL = 'https://.../extension/version.json';
    async function checkForUpdate() {
      const res = await fetch(UPDATE_URL + '?t=' + Date.now(), { cache: 'no-store' });
      if (!res.ok) return { updateAvailable: false };
      const data = await res.json();
      const updateAvailable = compareVersion(data.version, VERSION) > 0;
      await chrome.storage.local.set({ updateInfo: {
        current: VERSION, latest: data.version, updateAvailable,
        downloadUrl: data.downloadUrl, notes: data.notes || '', checkedAt: Date.now() }});
      if (updateAvailable) {
        chrome.action.setBadgeText({ text: 'NEW' });
        chrome.action.setBadgeBackgroundColor({ color: '#ef4444' });
      } else chrome.action.setBadgeText({ text: '' });
      return { updateAvailable, latest: data.version, downloadUrl: data.downloadUrl, notes: data.notes };
    }
    function compareVersion(a, b) {                 // "16.0.7" vs "16.0.10" 안전 비교
      const pa = String(a||'0').split('.').map(Number), pb = String(b||'0').split('.').map(Number);
      for (let i = 0; i < 3; i++) {
        if ((pa[i]||0) > (pb[i]||0)) return 1;
        if ((pa[i]||0) < (pb[i]||0)) return -1;
      }
      return 0;
    }
    chrome.runtime.onInstalled.addListener(() => checkForUpdate());
    chrome.runtime.onStartup.addListener(()   => checkForUpdate());
    chrome.alarms.create('updateCheck', { periodInMinutes: 180 });   // 3시간
    chrome.alarms.onAlarm.addListener(a => { if (a.name === 'updateCheck') checkForUpdate(); });

  웹앱 팝업: content-website.js 가 CHECK_UPDATE 후 우하단 카드 표시.
    localStorage['doctorvoice-update-dismissed'] = 무시한 latest 버전 → 같은 버전은 재표시 안 함.
  확장 팝업: 신호등(초록=연동중 / 주황=업데이트 필요 or 웹사이트 안 열림)

── 14-4. pack-crx.ps1 (패키징 스크립트 전문) ────────────────────────────────

  # 주의: 이 파일은 ASCII 만 사용. PowerShell 5.1 은 .ps1 을 ANSI 로 읽어
  #       비ASCII 주석/here-string 에서 깨진다.
  $ErrorActionPreference = "Stop"
  $src = $PSScriptRoot
  $pem = Join-Path $src "keys\doctorvoice.pem"
  if (-not (Test-Path $pem)) { throw "signing key missing: $pem" }

  # ConvertFrom-Json 은 PS5.1 에서 UTF-8 파일에 체하므로 regex 로 버전 추출
  $manifestText = Get-Content (Join-Path $src "manifest.json") -Raw -Encoding UTF8
  $version = ([regex]::Match($manifestText, '"version"\s*:\s*"([0-9.]+)"')).Groups[1].Value
  if (-not $version) { throw "could not read version from manifest.json" }

  $base  = Join-Path $env:TEMP ("dvpack-" + [guid]::NewGuid().ToString("N"))
  $stage = Join-Path $base "doctorvoice-ext"
  New-Item -ItemType Directory -Path $stage | Out-Null
  New-Item -ItemType Directory -Path (Join-Path $stage "icons") | Out-Null
  foreach ($f in @("manifest.json","background.js","naver-poster.js","content-login.js",
                   "gemini-writer.js","content-website.js","content.css",
                   "popup.html","popup.js")) {
    Copy-Item (Join-Path $src $f) (Join-Path $stage $f)
  }
  foreach ($ic in @("icon16.png","icon48.png","icon128.png")) {
    Copy-Item (Join-Path $src "icons\$ic") (Join-Path $stage "icons\$ic")
  }

  $chrome = @("$env:ProgramFiles\Google\Chrome\Application\chrome.exe",
              "${env:ProgramFiles(x86)}\Google\Chrome\Application\chrome.exe",
              "$env:LOCALAPPDATA\Google\Chrome\Application\chrome.exe"
             ) | Where-Object { Test-Path $_ } | Select-Object -First 1
  if (-not $chrome) { throw "chrome.exe not found" }
  & $chrome --pack-extension="$stage" --pack-extension-key="$pem" --no-message-box | Out-Null
  Start-Sleep -Seconds 3

  $crx = Join-Path $base "doctorvoice-ext.crx"
  if (-not (Test-Path $crx)) { throw "crx not created" }
  $pub = Join-Path (Split-Path $src -Parent) "frontend\public\extension"
  Copy-Item $crx (Join-Path $pub "doctorvoice-extension.crx") -Force

  $xml = "<?xml version='1.0' encoding='UTF-8'?>`n" +
    "<gupdate xmlns='http://www.google.com/update2/response' protocol='2.0'>`n" +
    "  <app appid='cdmgfoemncdnoigiolpgaaompcmlfcpk'>`n" +
    "    <updatecheck codebase='https://doctor-voice-pro-ghwi.vercel.app/extension/doctorvoice-extension.crx' version='$version' />`n" +
    "  </app>`n</gupdate>`n"
  # BOM 없는 UTF-8 로 써야 크롬이 파싱한다
  $utf8NoBom = New-Object System.Text.UTF8Encoding($false)
  [System.IO.File]::WriteAllText((Join-Path $pub "updates.xml"), $xml, $utf8NoBom)

── 14-5. 릴리스 체크리스트 (순서 지킬 것) ───────────────────────────────────

  1) 코드 수정
  2) chrome-extension/manifest.json 의 "version" 올리기       ← 여기가 단일 진실
  3) chrome-extension/ 에서  .\pack-crx.ps1  실행
     → frontend/public/extension/doctorvoice-extension.crx + updates.xml 갱신
  4) zip 도 만들어 두기 (수동 설치용)

  5) frontend/public/extension/version.json 수정
     version / downloadUrl / notes / releasedAt  ★ 4번 zip 파일명과 일치시킬 것
  6) git commit + push → Vercel 자동 배포 (프론트는 push 로 배포됨)
  7) 확인: 팝업 신호등이 초록인지, PING 의 version 이 새 값인지
  ★ 백엔드(Fly.io)는 git push 로 배포되지 않는다. 백엔드 변경이 있으면 flyctl deploy 별도 실행.
  ★ 버전을 올렸는데 crx/version.json 을 안 올리면 hosted 버전과 안 맞아
    "업데이트 필요" 오탐이 계속 뜬다.

── 15-2. 새 .pem 으로 확장 ID 를 새로 만드는 절차 ───────────────────────────

  1) chrome://extensions → 개발자모드 → "확장 프로그램 압축" (key 없는 폴더로)
     → .crx + .pem 생성. .pem 을 keys/ 에 보관(git ignore).
  2) 생성된 확장의 ID 를 확인 → pack-crx.ps1 의 appid, .reg 값에 반영
  3) 그 .pem 의 공개키를 manifest.json "key" 에 넣는다(ID 고정)
     추출: openssl rsa -in key.pem -pubout -outform DER | openssl base64 -A
  ★ .pem 을 분실하면 ID 가 바뀌고 기존 사용자 전원이 재설치해야 한다. 백업 필수.

── 15-3. 다른 블로그 플랫폼(티스토리 등)으로 확장하려면 ─────────────────────

  바꿔야 하는 것은 naver-poster.js 하나다. background.js 는 거의 그대로 쓴다.
  새 poster 가 반드시 구현해야 하는 메시지 인터페이스:

    PING            → { ok, version, editor:boolean }
    GET_POSITIONS   → { ok, title:{x,y}, body:{x,y} }   ★ iframe 오프셋 포함 절대좌표
    DISMISS_POPUP   → { ok }
    INSERT_IMAGES   → { ok, inserted, expected, failed[] }  ★ 실제 증가 검증 필수
    FINALIZE        → { ok, done, action, categories?, error? }
    READ_CATEGORIES → { ok, categories:[{id,name}], error? }
    READ_BLOG_ID    → { ok, blogId }   ← 못 찾으면 응답하지 말 것
    PROGRESS / HIDE_OVERLAY

  그리고 manifest 의 content_scripts matches + host_permissions 에 새 도메인 추가.

── 15-4. 웹앱 없이 확장 단독으로 쓰려면 ─────────────────────────────────────

  popup.html 에 폼을 추가해 popup.js 에서 직접 호출하면 된다:
    chrome.runtime.sendMessage({ action:'SUBMIT_JOB', job })   ← 내부 메시지
  단, 현재 background 의 SUBMIT_JOB 은 onMessageExternal 에만 있으므로
  onMessage 쪽에도 같은 분기를 추가해야 한다.
  배치는 payload pull 구조(REQUEST_JOB)가 웹 페이지를 전제하므로,
  단독 사용 시에는 job 전체를 한 번에 넣는 경로(hasPayload=true)만 쓴다.

── 15-5. 이식 후 동작 확인 순서 (스모크 테스트) ─────────────────────────────

  1) 확장 로드 → 팝업 열기 → 버전 표시 정상?
  2) 웹앱 접속 → 팝업 신호등 초록? (localStorage 에 extension-id 심겼는지 확인)
  3) PING 왕복 확인 (콘솔에서 chrome.runtime.sendMessage(id,{action:'PING'},console.log))
  4) SYNC_BLOG → blogId 정상 반환?  (네이버 로그인 필요)
  5) SYNC_CATEGORIES → 카테고리 목록 반환?
  6) SUBMIT_JOB { finalAction:'draft' } 로 임시저장 1건 → 네이버에서 확인
  7) 사진 1장 넣고 draft → 실제로 삽입됐는지 확인 (★ imageComponentCount 검증)
  8) SUBMIT_JOB { finalAction:'schedule', schedule:{datetime: 내일 날짜} }
     → ★ 반드시 "내일 이후" 날짜로. 오늘로 테스트하면 datepicker 이동 로직이 검증 안 됨
     → 네이버 예약발행 목록에서 날짜/시각 확인
  9) 배치 2건으로 SUBMIT_BATCH → 결과 이벤트 2건 + 준비함 동작 확인
  10) 팝업 "진단 로그 복사" → 로그가 남는지 확인

  · 이미지 컴포넌트 클래스 미실측

  · 캡차는 자동 해결 불가(cross-origin). 사용자 핸드오프가 유일한 대응.
  · MV3 워커가 죽으면 진행 중이던 job(메모리)은 사라진다.
    pendingJob(storage)로 글쓰기 복귀는 되지만 배치 진행 상태는 복구되지 않는다.
