# 원스톱 자동 운영 UX/UI

## 사용자 목표

### 대량 작업을 기본으로 전환

네이버 검색 키 연결 후속 수정: `naver_search_credentials.resolve`가 요청 사용자 본인의 아웃리치 저장 키를 먼저 읽고, 없거나 복호화할 수 없으면 서버 OpenAPI 키 쌍으로 대체한다. 사전 검사와 실제 근거 검색에서 동일한 해석기를 사용한다. 검색광고 `NAVER_AD_*`는 검색량 조회용이며 OpenAPI 키와 호환되지 않는다. 사용자별 저장 키·격리·서버 대체·복호화 실패·검색 요청 헤더를 포함한 관련 검사 22개 통과 후 Fly `deployment-01M22NYAKH7KEDTQZ87SS1DCG3`에 배포하고 상태 검사를 통과했다. 실제 사용자의 저장 키 유효성은 확인하지 않았다. 기존 아웃리치 저장 방식은 `ENCRYPTION_KEY`가 없는 경우 임의 키를 사용하므로 과거 암호문을 복호화할 수 없는 가능성은 별도 점검이 필요하다.

반복 운영만 간소화한 화면은 총 30개 또는 50개를 한 번에 준비하려는 사용자에게 맞지 않았다. 기본 화면을 `한 번에 대량 발행`으로 바꾸고 기존 반복 운영은 `매일 자동 운영`에서 선택한다. 대량 입력창을 현황 카드보다 위에 배치했다.

- 총 원고 수는 10·30·50개 버튼 또는 1~50 직접 입력, 랜딩 URL은 선택 사항이다.
- 시작 요청 하나로 키워드 발굴, 근거 확인, 엄격한 원고 검수, 사진 준비, 예약 배정을 실행한다. 키워드 수동 선택은 필요 없다.
- 실제 예약은 연결된 블로그의 일일 한도·운영 시간·기존 예약을 지키며 최대 90일 범위에서 배정한다. 같은 시각에 일괄 게시하는 기능이 아니다.
- 적합한 키워드가 부족하거나 검수가 실패하면 요청 수보다 적게 예약될 수 있다. 키워드 선정 수·검수 통과 수·예약 수·자리 부족 수를 구분한다.
- 진행 중인 서버 작업은 새로고침 시 복원한다. 중복 시작 요청은 기존 작업을 반환한다. 준비 중단은 기존 예약을 취소하지 않는다.
- 반복 운영이 켜진 경우 먼저 일시정지한다. 서버가 검수한 대량 원고에는 실행 출처와 사진 기준을 기록하여, 반복 운영 일시정지가 별도 대량 예약 실행까지 막지 않도록 했다. 대량 원고도 발행 직전 검수 승인 일치 여부를 검사한다.
- API·파이프라인·반복 운영 검사 22개와 Vercel 프로덕션 빌드가 통과했다. 운영 웹에서 테스트 API를 사용하는 글 수 선택·시작·새로고침 복원·중단·모바일 동선 검사도 통과했다. 실제 네이버 계정으로 글 생성·발행은 실행하지 않았다.
- 대량 화면 운영 배포: Vercel `dpl_EJGmLU1TP9wgKtJQnd5BH1ePtfk4`, Fly 이미지 `deployment-01M22JPHFFDVAXHF0CH1W2FNK6`. 운영 주소는 동일하며 OpenAPI의 `discover_keywords`, `quality` 필드와 `/health` 정상 응답을 확인했다. 아래 최초 배포 기록을 대체하는 최신 배포다.

사용자는 진료 항목과 원하는 랜딩페이지를 알려주고, 하루 발행 목표를 정한 다음 운영을 시작한다. 키워드 추출·선별, 글 분량·검수 점수·수정 횟수, 사진 배치와 예약 슬롯을 매번 직접 정하지 않아도 된다.

‘원스톱’이라는 이름의 기존 4단계 도구와 캠페인 반복 자동화가 서로 다른 화면에 있던 문제를 해결한다. `/dashboard/one-stop`을 기본 시작점으로 통합하고, 사이드바 시작 그룹에 배치했다. 예전 도구는 `/dashboard/one-stop/manual`에서 계속 열 수 있다.

## 화면과 동선

| 상황 | 가장 먼저 보여주는 정보 | 주된 행동 |
| --- | --- | --- |
| 첫 방문, 운영 공간 없음 | 병원·진료 항목·블로그·사진을 연결하는 단일 폼 | 저장하고 발행 기준 정하기 |
| 기존 병원이 있음 | 저장된 병원 선택, 등록된 블로그 재사용 | 운영 공간 만들기 |
| 운영 시작 전 | 하루 발행 목표, 사진 수, 랜딩 URL·목적 | 자동 운영 시작 |
| 운영 중 | 목표 발행량, 현재 작업, 공개·예약·대기·확인 건수 | 일시정지 또는 필요한 항목 해결 |
| 로그인 만료·보안문자 | 해당 블로그와 PC에서 해야 할 일 | 실행기 Chrome에서 로그인·보안문자 처리 |
| 등록 결과 불명확 | 해당 글과 확인 필요 이유 | 발행 현황의 대조 화면 열기 |
| 원고 품질 미달 | 자동 발행에서 제외됐다는 설명 | 필요할 때 원고 확인 |

첫 설정은 하나의 폼 제출과 발행 기준 확인 후 시작으로 구성한다. 실행기 다운로드·압축 해제·로그인은 최초에 별도로 필요하다. 이미 설정·로그인이 유지되는 사용자는 운영 시작 버튼 한 번으로 서버 자동 운영을 재개할 수 있다. 네이버 로그인이나 캡차까지 ‘한 번의 클릭으로 끝난다’고 표시하지 않는다.

첫 설정 자체로 생성이나 발행을 시작하지 않는다. 사진 업로드 도중 실패하면 저장된 병원·운영 공간을 같은 화면에서 재사용한다. 이 복구 정보는 현재 탭의 메모리에 보관되므로 업로드 응답이 유실되거나 탭을 닫은 경우에는 사진 풀과 운영 목록에서 결과를 확인해야 한다.

## 정보 배치와 디자인

- 기존 앱의 글꼴·색상·카드·버튼을 유지한다. 시작 화면의 넓은 상단 영역에는 목적과 세 가지 큰 단계만 표시한다.
- 원스톱 화면의 사이드바는 홈·원스톱·운영 목록·병원 관리·사진만 먼저 보여준다. 나머지 기능은 ‘전체 도구 보기’로 펼친다.
- 데스크톱은 왼쪽 운영 설정·현재 상태, 오른쪽 최초 연결·실행기 안내로 구성한다. 모바일은 한 열로 쌓고 현황은 두 열로 배치한다.
- 운영 중에는 긴 입력폼을 접고 상태 카드와 일시정지 버튼을 보여준다. 재시작 때 저장된 값을 불러온다.
- 본문 분량, 검수 점수, 수정 횟수, 준비 일수, 생성 시도 한도는 고급 설정에서 변경한다. 기본 품질 기준은 그대로 적용한다.
- 링크 안내 문구·UTM 추적과 랜딩 설정만 저장하는 별도 동작은 펼침 영역에 둔다.
- 기본 입력은 하루 발행량과 선택 사항인 랜딩 URL로 줄였다. 페이지 목적은 URL을 입력했을 때만 표시하며 선택 사항이다. 사진 수는 세부 설정으로 옮겼고, 자동 운영 시작 버튼은 카드 전체 너비로 표시한다. 상단 설명도 줄여 설정까지 이동하는 거리를 줄였다.
- 공개 확인·네이버 예약 등록·준비 대기는 별도 건수로 표시한다. 등록 확인을 실제 공개로 표현하지 않는다.
- 경고에는 원인과 다음 행동을 함께 표시한다. 조회 실패 시 기존 현황임을 알리고, 시작 실패 안내가 주기적 조회 때문에 사라지지 않게 했다.
- 연결 상태에서 ‘사진 세트 선택’과 ‘블로그 등록’을 실제 로그인·온라인 상태로 표현하지 않는다. 실행기 실시간 연결 감지는 아직 없음을 안내한다.
- 원스톱 첫 설정 위에 기존 온보딩 모달과 튜토리얼을 겹쳐 띄우지 않는다. 확장프로그램 상태 배지도 이 화면에서는 숨겨 PC 실행기와 확장을 모두 설치해야 한다는 오해를 줄인다.
- 키워드·원고·사진·예약 6단계 세부 관리는 캠페인 화면에서 펼칠 때만 표시한다. 오류 해결 링크의 `?step=3`, `?step=6`은 필요한 관리 단계를 바로 연다.
- Windows 실행기 ZIP은 `/downloads/DoctorVoiceAutopilot.zip`에 포함해 다운로드 버튼이 실제 파일을 가리키도록 했다. 운영 배포 후 해당 주소의 HTTP 200과 파일 크기 74,884,260바이트를 확인했다.
- **2026-09-10 변경**: ZIP 대신 Inno Setup 설치 파일 `/downloads/DoctorVoiceAutopilotSetup.exe`(52,500,475바이트)를 내려받게 했다. 압축을 푼 폴더를 크롬 확장으로 로드하려다 `_asyncio.pyd` 이름 때문에 실패하는 사고가 있었고, 설치 파일에는 압축 풀기 단계 자체가 없다. 카드 문구도 설치 → SmartScreen 통과 → 로그인 3단계로 바꿨다. 로컬 빌드본을 이 PC에 실제 설치해 바로가기·제거 항목·실행까지 확인했고, 배포 주소의 HTTP 200 확인은 아직이다.

## 검증 기준

`frontend/tests/automation_ux_smoke.py`는 실제 로컬 Next 서버에 Playwright 브라우저로 접속하되 외부 API는 모두 대역으로 처리한다. 시작 시 랜딩 설정 전송, 새로고침 후 운영 상태 복원, 일시정지, 모바일 가로 넘침, 첫 설정에서의 불필요한 모달 부재, 첫 설정의 발행 미실행, 검증 오류 메시지 유지, 브라우저 실행 오류를 확인한다.

화면 캡처는 `docs/ux-preview/`에 저장하며 데이터는 테스트용이다. 이 검증은 실제 AI 글 품질, 네이버 계정 연결·예약 발행, 실제 사용자 대상 사용성 평가를 대신하지 않는다. 고품질 완전 자동 발행을 운영 환경에서 입증하려면 앞선 자동화 문서에 명시한 실계정·배포 검증이 추가로 필요하다.

로컬 검증에서 위 브라우저 동선 검사를 통과했다. TypeScript·프로덕션 빌드도 통과했으며 51개 페이지가 생성됐다. 기존 결제 설정 페이지의 클라이언트 렌더링 경고는 남아 있다. 이후 사용자 요청에 따라 아래 운영 배포를 완료했다.

실행기 소스의 웹 화면 열기 주소는 `/dashboard/one-stop`으로 변경했다. 이 변경을 포함한 EXE 재빌드는 생성까지 완료됐지만 Windows 애플리케이션 제어 정책(WinError 4551)이 자체 점검 실행을 차단해 ZIP 갱신은 중단됐다. 정책 우회나 미검증 패키지 교체는 하지 않았다. 현재 다운로드 ZIP은 앞서 자체 점검을 통과한 버전이며 웹 화면 열기 버튼은 `/dashboard/campaign`을 연다. 해당 화면에서 원스톱으로 이동할 수 있다. 현재 ZIP SHA-256은 `c801441d0aafb3ccd0e0529e9b8e815420d4aa03980b274101432d113058c689`이다.
